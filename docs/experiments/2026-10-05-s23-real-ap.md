# Samsung S23 on the real D-Link AP: full AAA test (2026-10-05)

- **Status:** partly passed. Authentication, authorization and accounting passed; revocation failed on this AP.
- **Who / where:** project team, hostel room, AP wired into a hostel wall socket
- **Report built from it:** `reports/s23-aaa-test/` (web page https://claude.ai/artifact/NFTg769D6M7HupHoQFcjkn + PDF)
- **Written:** 2026-10-07, reconstructed from the database, detail files and session notes. The container log lines from that day were already lost.

## Aim
Prove that a normal Android phone can log in to WPA2-Enterprise through a real AP using our FreeRADIUS + OpenLDAP lab. Check that the group policy is applied and every session is recorded. Then test whether a disabled user can be removed.

## Observations
- Totals for the S23: 3 sessions, 3775 s, 24.96 MB up, 736.66 MB down.
- Accounting records `WLAN-Group-Cipher = 1027074` (TKIP), because the AP was set to WPA mode AUTO and cipher Auto.
- The AP sends Interim-Updates every 300 s (sessions A and B). Session C had none.

## Inferences (not yet tested)
- Session C reused cached PMK keys, so the AP never asked RADIUS. Test: forget the network on the phone, reconnect while disabled, and expect an Access-Reject.
- The DAP-X3060 has no RFC 5176 support at all, rather than a configuration problem. Test: ask D-Link support, naming firmware v1.01.

## Problems met and fixes
- No RADIUS request reached the server → the AP pointed at the old laptop IP (.184) → set .243 in both the RADIUS and accounting fields, then Save and Activate.
- Accounting times showed 2024 → the AP clock is not synced → use server receive times; set NTP on the AP (still open).
