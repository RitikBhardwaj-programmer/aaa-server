Campus Wi-Fi AAA Lab

A personal Wi-Fi login for every student, built with OpenLDAP and FreeRADIUS in Docker. This page explains the whole system: how one login travels through it, and what every file in the repository does.

28 / 28 end-to-end tests pass FreeRADIUS 3.2.10 OpenLDAP 2.5.13 PEAP-MSCHAPv2 + EAP-TTLS/PAP UDP 1812 / 1813 AP: DIR-X6060 Enterprise support unconfirmed

01The problem

The college Wi-Fi uses one shared password. This lab replaces it with one identity per person.

With a shared password (WPA2-Personal), everybody who knows it can connect. You cannot tell who connected, and you cannot block one person. If the password leaks, you must change it for everyone.

WPA2-Enterprise (802.1X) fixes this. Each person logs in with their own user ID and password, for example 24IT001. The access point does not check the password itself. It asks a central server, which checks a central directory. That central server is the subject of this lab.

WPA2-Personal (today)WPA2-Enterprise (this lab)
CredentialOne password for allOne user ID + password per person
Block one userNot possibleAdd the user to cn=disabled
Who was online?UnknownEvery session logged with user, device, time, bytes
Different rules per groupNoSession limit and VLAN per LDAP group
Password leakChange it for everyoneReset one account

02Architecture

Four containers on one Windows PC. Only FreeRADIUS is reachable from the network.

Each protocol covers one hop:

  • EAPOL carries EAP between the device and the AP. The device has no IP address yet at this point.
  • RADIUS carries the same EAP messages between the AP and FreeRADIUS, inside EAP-Message attributes.
  • LDAP is how FreeRADIUS finds the user, checks the password and reads group membership.

Only after an Access-Accept does the AP open the port. Then the device uses DHCP to get an IP address.

Design decisions

  • Fixed subnet 10.89.0.0/24. Your campus LAN is 172.17.28.0, which overlaps Docker's default 172.17.0.0/16. A fixed subnet avoids that conflict.
  • Fixed IPs. clients.conf identifies the test runner by 10.89.0.50, so its address must not change.
  • Explicit environment lists. Each service gets only the secrets it needs. For example, ldap never sees the RADIUS shared secrets.
  • Health-gated start. radius and ldapadmin wait until ldap is service_healthy. The health check is an anonymous rootDSE search.
  • Test profile. tests starts only with --profile test, so docker compose up does not run it.

07OpenLDAP container

The identity store. It holds users, password hashes and group membership.

ldap/Dockerfile — two stages

PEAP-MSCHAPv2 needs the sambaNTPassword attribute, which is defined in the Samba LDAP schema. Debian ships that schema only inside the large samba package. Stage 1 downloads the .deb and extracts the one file. Stage 2 installs only slapd, ldap-utils and openssl, then copies the schema in. The final image contains no Samba binaries.

ldap/Dockerfile (excerpt)
FROM debian:bookworm-slim AS schema
RUN apt-get update \
 && cd /tmp && apt-get download samba \
 && dpkg-deb --fsys-tarfile samba_*.deb | tar -x ./usr/share/doc/samba/examples/LDAP/samba.ldif
...
COPY --from=schema /tmp/usr/share/doc/samba/examples/LDAP/samba.ldif /etc/ldap/schema/samba.ldif

ldap/entrypoint.sh — first start

On every start the script checks for /etc/ldap/slapd.d/cn=config.ldif. If the file is missing, the volumes are empty, so the script builds the directory. Then it runs slapd in the foreground.

The generated cn=config loads five schemas: core, cosine, nis, inetorgperson and samba. It defines one MDB database for dc=nitsrinagar,dc=edu, with indexes on objectClass, uid, member and cn. The admin password is stored only as a {SSHA} hash in olcRootPW.

Access control (olcAccess)

LDAP checks rules in order, and the first rule whose target matches decides. ROOT_PEER is the identity of the root user over the local socket; scripts inside the container use it, with no password.

#TargetWho gets whatWhy
{0}userPasswordroot: manage · anonymous: auth only · others: noneAnyone can bind (log in), nobody can read the hash
{1}sambaNTPassword, sambaLMPasswordroot: manage · cn=radius: read · others: noneOnly FreeRADIUS needs the NT hash, for MSCHAPv2
{2}cn=admin entry: entry, objectClass, cnanonymous: read · others: continue to the next rulephpLDAPadmin looks up the login entry before it binds
{3}everything elseroot: manage · cn=radius: read · self: read · others: noneAnonymous users cannot list the directory. Users see only their own entry.

Directory tree

ldap/add-user.sh — one user, two hashes

Each user entry has two object classes: inetOrgPerson (name, mail, password) and sambaSamAccount (NT hash). The script computes both hashes from one password:

ldap/add-user.sh (excerpt)
ssha=$(slappasswd -h '{SSHA}' -s "$password")
nt_hash=$(printf '%s' "$password" | iconv -f UTF-8 -t UTF-16LE \
    | openssl dgst -md4 -provider default -provider legacy | awk '{print toupper($NF)}')
  • {SSHA} is salted SHA-1. EAP-TTLS/PAP uses it, because FreeRADIUS sends the plain password to LDAP as a bind.
  • The NT hash is MD4 of the UTF-16LE password. MSCHAPv2 is a challenge-response method, so the server must hold this hash. OpenSSL 3 keeps MD4 in its legacy provider. The function was checked against the known vector: NT hash of password = 8846F7EAEE8FB117AD06BDD830B7586C.
  • sambaSamAccount requires a sambaSID. The script uses a fixed lab domain S-1-5-21-1000-2000-3000 plus RID 1001 + count of existing accounts.
  • Groups are groupOfNames, which must have at least one member. So the script creates a group when its first member arrives, and modifies it after that.
  • The password comes from $NEW_USER_PASSWORD. If that is empty, the script generates one and prints it once. It is never a command-line argument, so it does not appear in shell history or the process list.

08Certificates

PEAP and TTLS start with TLS. The device must check that it talks to the real server.

certs/make-certs.sh runs once, inside the FreeRADIUS image, which has openssl. It writes ca.pem, ca.key, server.pem and server.key, with the keys at mode 600. It refuses to overwrite an existing server.pem.

Why this matters: without a server-certificate check, a fake AP with its own RADIUS server could complete the TLS handshake and collect MSCHAPv2 responses. Test group 3 proves that the client aborts on a name mismatch.

09FreeRADIUS container

The official image, plus seven replaced files and two sed edits.

radius/Dockerfile

  • Copies the 7 config files over the stock ones.
  • Enables the ldap and sql modules with symlinks in mods-enabled/.
  • Sets auth = yes in radiusd.conf, so every accept and reject is logged with its reason. The password is never logged.
  • Turns on the class column in the stock SQLite queries, with %{string:&Class} so the group name is stored as text, not hex.
  • Starts with -l stdout, so docker compose logs radius shows the server log.

radius/radius-start.sh

The certificates arrive from the Windows folder, where Linux file ownership has no meaning. The script copies them to /etc/freeradius/certs/lab and gives the private key owner root:freerad and mode 0640, because FreeRADIUS runs as user freerad. It also creates the sqlite/ and radacct/ folders. Then it calls the image's normal entrypoint.

raddb/mods-available/ldap

radius/raddb/mods-available/ldap (excerpt)
identity = "cn=radius,ou=Services,$ENV{LDAP_BASE_DN}"
password = "$ENV{LDAP_RADIUS_PASSWORD}"
update {
	control:NT-Password := 'sambaNTPassword'
}
user {
	filter = "(&(objectClass=inetOrgPerson)(uid=%{%{Stripped-User-Name}:-%{User-Name}}))"
}
group {
	base_dn = "ou=Groups,${..base_dn}"
	filter = '(objectClass=groupOfNames)'
	membership_filter = "(member=%{control:LDAP-UserDn})"
}
  • Lookup: binds as the read-only cn=radius account and searches by uid. FreeRADIUS escapes the user name, so LDAP filter injection is not possible.
  • NT hash: copies sambaNTPassword into control:NT-Password for mschap.
  • Password check for PAP/TTLS: Auth-Type LDAP binds as the user's DN with the given password. FreeRADIUS never sees the SSHA hash.
  • Groups: membership_filter searches ou=Groups for groups whose member is the user. This makes the LDAP-Group == "faculty" check work without a memberOf overlay.

raddb/mods-available/eap

  • default_eap_type = peap. The ttls and peap sub-modules both send the inner request to virtual_server = "inner-tunnel".
  • Only peap, ttls and mschapv2 are loaded. MD5, GTC and LEAP are left out because they are weak.
  • TLS: our lab certificates, tls_min_version = "1.2", tls_max_version = "1.2" (TLS 1.3 inside PEAP/TTLS is still unreliable on many clients), cipher list HIGH:!aNULL:!MD5:!RC4:!3DES.
  • use_tunneled_reply = no. The inner result goes out through session-state instead (see section 10).

raddb/mods-available/sql

The sql module is used only for accounting and the post-auth log. It never looks up users; LDAP is the only identity store. Driver rlm_sql_sqlite, database ${logdir}/sqlite/radius.db. The bootstrap option creates the standard schema the first time.

radius/raddb/mods-available/sql (excerpt)
# Log the real (inner) identity, not the anonymous outer identity of PEAP/TTLS
sql_user_name = "%{%{reply:User-Name}:-%{%{session-state:User-Name}:-%{User-Name}}}"

The fallback chain reads: use the reply's User-Name if there is one (an accept), else the inner identity saved in session-state (a reject inside the tunnel), else the request's User-Name (plain PAP and accounting).

10Request processing: default and inner-tunnel

Two virtual servers. The outer one talks to the AP. The inner one sees the real user inside TLS.

sites-available/default (outer)

  • listen: auth and acct on all addresses. port = 0 means the standard ports, 1812 and 1813.
  • authorize: eap { ok = return } stops early while an EAP conversation is in progress. LDAP is called only when there is no EAP-Message, so the server does not look up "anonymous" on every TLS round.
  • authenticate: Auth-Type LDAP (bind) for PAP, eap for everything else.
  • preacct / accounting: acct_unique builds a stable session key. Then the detail and sql modules write the record.
  • post-auth: copies the six authorization attributes from session-state into the reply with :=, logs to SQL, and removes Reply-Message for EAP. Some clients reject an EAP packet that carries one.
radius/raddb/sites-available/default — post-auth
update reply {
	&User-Name := &session-state:User-Name
	&Session-Timeout := &session-state:Session-Timeout
	&Tunnel-Type := &session-state:Tunnel-Type
	&Tunnel-Medium-Type := &session-state:Tunnel-Medium-Type
	&Tunnel-Private-Group-Id := &session-state:Tunnel-Private-Group-Id
	&Class := &session-state:Class
}

sites-available/inner-tunnel

The inner server listens on 127.0.0.1:18120 for debugging only. Normal traffic reaches it internally from the peap and ttls modules.

# Converts the hex NT hash from LDAP to binary, as mschap needs. Auth-Type is already set above.
pap
  • mschap sets Auth-Type MS-CHAP when MS-CHAP attributes are present (PEAP).
  • ldap finds the user and loads the NT hash.
  • When there is a plain User-Password (TTLS/PAP), the if block selects an LDAP bind.
  • pap runs last only to convert the 32-character hex NT hash into 16 bytes. Without it, MSCHAPv2 failed; see section 17.

In post-auth, the inner server runs campus_authorize and then hands the result to the outer server. This is needed because the outer and inner requests are separate. For PEAP, the final Access-Accept is sent one round later than the inner accept, and session-state survives between rounds through the RADIUS State attribute.

12Accounting

Every session is recorded twice: in a queryable database and in plain text.

  • SQLite: /var/log/freeradius/sqlite/radius.db in volume radius-acct. Table radacct holds sessions; table radpostauth holds every accept and reject, with the real user name and the group.
  • Detail files: radacct/<source-ip>/detail-YYYYMMDD, one text record per packet.
  • Why SQLite: no extra database server, which keeps the "no PostgreSQL" decision. A later Spring Boot dashboard can still read it with SQL.

scripts/acct.ps1 shows the last 20 sessions. It opens the database with ?immutable=1 from the tests image, so it can never change the data.

13phpLDAPadmin

A web UI for the directory, reachable only from this PC at 127.0.0.1:8080.

Version 2 is a full rewrite by the project's own maintainer (leenooks); v1.2 is deprecated for security reasons. Getting the admin login to work needed three settings, found one at a time:

  1. LDAP_LOGIN_ATTR: DN — log in with a full DN. It must be uppercase.
  2. A real entry at cn=admin,dc=nitsrinagar,dc=edu. phpLDAPadmin refuses a rootDN that has no entry. The bind still checks olcRootPW.
  3. ACL rule {2}: phpLDAPadmin looks up the entry anonymously before it binds, so anonymous users may read that one entry's objectClass and cn.

LDAP_LOGIN_OBJECTCLASS: organizationalRole adds a safety rule. Only the admin entry has that class, so Wi-Fi users (inetOrgPerson) cannot log in to the admin UI. This was tested: admin gets in, student001 is refused.

How the assertions read attributes

tests/run-tests.sh (excerpt)
# Last value of RADIUS attribute number $1 in eapol_test output $2 (the Access-Accept is the last packet)
attr() { awk -v n="$1" '$1=="Attribute" && $2==n {getline; v=$2} END {print v}' "$2" | tr -d "'"; }
hex2str() { [ -n "$1" ] && printf '%b' "$(echo "$1" | sed 's/../\\x&/g')"; }

eapol_test prints each attribute by number, with its value on the next line. Octet values such as VLAN "20" appear as hex 3230, so hex2str decodes them. One test line then compares a single string: SUCCESS 43200 20 faculty faculty001.

16The Docker NAT problem

FreeRADIUS never sees the AP's real IP address on Docker Desktop for Windows.

RADIUS identifies each NAS by its source IP address, then checks the shared secret. Because every LAN packet arrives from 10.89.0.1, the AP entry in clients.conf uses that address. So the shared secret is the only proof that a packet comes from the AP. That is why RADIUS_SECRET_AP is 32 random characters.

A check on NAS-IP-Address was considered and rejected. Anyone who has the secret can forge that attribute, and consumer routers sometimes fill it with an unexpected address. On a Linux host with host networking, you can change ipaddr back to $ENV{AP_IP}.

The path was verified: a container outside the lab network sent a full PEAP login through the published port with the AP secret. The server log showed Login OK: [student001] (from client ap-dirx6060 …).

17Bugs found and fixed

Each one was found by a failing test or a debug trace, not by guessing.

PEAP failed: "No NT-Password". The debug trace showed that LDAP did return the hash, as a 32-character hex string, but mschap needs 16 raw bytes. The stock inner-tunnel calls pap at the end of authorize, which converts it. Fix: add pap after the LDAP block.

Accept logged as "anonymous", with two User-Names. The outer reply already contained User-Name = "anonymous", and the stock-style &reply: += &session-state: added a second one. The AP would see two identities. Fix: copy only the six policy attributes, with :=. This also stopped internal TLS attributes from leaking into the reply.

Class stored as hex. Class is an octets attribute, so SQLite stored 0x73747564656e7473. Fix: write it with %{string:&Class}.

AP would be "unknown client". Docker Desktop's NAT, described in section 16. Fix: match the gateway address.

phpLDAPadmin admin login refused. Three separate causes, described in section 13.

18Security model

ThreatControl in this lab
Fake AP collects passwordsPrivate CA + server-name check (radius.nitsrinagar.lab); tested in group 3
Password sniffed over the airThe inner method runs only inside TLS 1.2; the outer identity is anonymous
Forged RADIUS packets (BlastRADIUS, CVE-2024-3596)require_message_authenticator = yes and limit_proxy_state = yes for the AP
Rogue NASPer-client shared secrets, 32 random characters; a wrong secret is dropped (tested)
Hash theft from LDAPACLs: nobody reads userPassword; only cn=radius reads the NT hash; anonymous users list nothing
LDAP filter injection via user nameThe ldap module escapes values inserted into filters
Admin UI exposedBound to 127.0.0.1; only the organizationalRole admin can log in
Secrets in git.env and certs/* ignored; checked with git check-ignore before the commit

Known weakness. The NT hash is unsalted MD4. PEAP-MSCHAPv2 cannot work without it. Users who connect only with EAP-TTLS/PAP would not need it.

19Next: the real AP

The server is ready. The open question is the hardware.

  1. In the DIR-X6060 web UI, open Settings → Wireless → Security Mode. Look for a WPA2-Enterprise option.
  2. If it is there: connect this PC to the D-Link network, give the PC a fixed IP, and add the firewall rule for UDP 1812–1813 (README §6.2).
  3. In the router, set the RADIUS server to the PC's IP, port 1812, secret RADIUS_SECRET_AP. If there is an accounting field, set port 1813.
  4. On a phone, install ca.pem, choose PEAP / MSCHAPv2, set the domain radius.nitsrinagar.lab, and log in as student001.
  5. Watch docker compose logs -f radius for Login OK, then run .\scripts\acct.ps1.

If the router has no Enterprise mode, use a D-Link DAP business AP or an OpenWrt device. The server side does not change.
